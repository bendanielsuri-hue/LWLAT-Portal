# Mobile bottom nav bar, not a persistent icon rail, below 480px

At phone width the hub sidebar previously auto-collapsed to a 64px icon-only rail (tablet still does, `@media (max-width: 900px)` in `responsive.css`) — on a 375px screen that still eats a meaningful slice of the one thing this size class has least of: horizontal width (#129, following on from #114's responsive work). Below a dedicated 480px phone tier, `templates/hubs/_hub_sidebar.html` now hides the sidebar entirely and renders a fixed bottom nav bar instead.

Key calls made across the #129 grilling/prototype session, in case a future reader asks "why is it built this way":

- **Bottom, not top.** Thumb-reachable, and matches the platform convention users already have muscle memory for.
- **Fixed 3 buttons (Menu / Search / +Referral), not one tab per page.** A hub can have anywhere from 3 to 8+ local pages — enumerating them all as icons either forces an arbitrary cap-plus-overflow scheme or shrinks unreadably. Putting page navigation behind a Menu sheet sidesteps the question entirely: nothing needs to be cut.
- **Hub-switching folded into the Menu sheet, not its own bar button.** Once inside a hub on a phone, users are almost always navigating between that hub's own pages, not jumping hubs — a rare action doesn't need a permanent bar slot. "Back to `{{ back_to_hub_label }}`" (Panel's existing `back_to_hub_url`) and "Switch Hub" sit as a primary/secondary button pair at the top of the Menu sheet instead, above the hub's own name.
- **+Referral is a raised centre FAB**, not a flush tab — the one action most likely to be the reason someone opened the bar at all.
- **Settings only appears as its own tab for MAT-wide staff** (`Staff.is_mat_staff`); a school-scoped user has nothing to switch schools *to*, so their Settings tab skips straight to Appearance instead of a two-option chooser. The current-user ("who am I") switcher stays desktop-only — it's the dev/testing identity mechanism (no real auth yet, `core/identity.py`), not something a real mobile user would touch.
- **Search prioritises in-app content search over the global hub-switcher search** when both exist on a page (Panel's `data-panel-search-trigger` vs. the sidebar's `#search-nav-overlay`) — searching *within* the app you're in is what "Search" means in-context.
- **Every popup — Menu/Settings (new) and the existing Search/+Referral dialogs and Switch Hub/School/Appearance overlay panels — is reskinned to one consistent bottom-sheet shape, colour, and slide transition at this breakpoint**, scoped via `body:has(.mobile-tabbar)` so it never touches desktop/tablet's centred-card/rail styling. Without this, sheets opened from the same bar looked and moved differently depending on which pre-existing component happened to back them.
- **Tap-anywhere-in-the-backdrop is the primary dismiss gesture**, not the corner × — a bottom sheet's dismiss target should be thumb-natural, not a top-right reach. The × stays as a small, familiar fallback.
