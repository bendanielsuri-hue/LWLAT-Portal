{% comment %} Disabled-button + tooltip wrapper. .btn-disabled sets pointer-events:none (buttons.css), which suppresses hover entirely - a `title` on the disabled element itself never shows a tooltip, so it has to sit on a plain wrapping element that still receives hover instead. `title` is optional: omit it when the label alone is explanation enough. .disabled-btn-tooltip-wrap (buttons.css: display: inline-flex + a fill rule for its .btn child) - when this sits as a flex item in a row of real buttons (e.g. Panel Meetings' own .meeting-card-actions), a plain inline wrapper becomes the actual flex item instead of the .btn inside it, but .btn's own inline-flex sizing still shrinks it to its natural content width regardless of the wrapper's own (differently- computed) flex box - the two disagreed and the button visually overflowed its own slot into the next one (live feedback, screenshot: "Start meeting looks like its colliding"). display: contents was the first fix for that and broke the tooltip itself - a contents box is no box, so there was nothing for the pointer to land on and no tooltip ever appeared. See that rule's own comment for the current shape. Params: classes (extra .btn modifier classes, e.g. "btn-secondary btn-sm"), icon (icon template path, optional), label (button text), title (tooltip text, optional). {% endcomment %} {% if title %}{% endif %} {% if icon %}{% include icon %} {% endif %}{{ label }} {% if title %}{% endif %}
